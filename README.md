# 同人誌の印刷所さがし

同人誌の印刷所 22 社を、判型・部数・予算と、入稿・支払い・納品の条件で絞り込み、基本のセットの値段の目安が安い順に並べるサイト。印刷所ごとの紹介ページ（原稿の決まり・背幅の計算・根拠のページ）もある。

**公開サイト（予定）: https://shiki365.github.io/doujin-printer-finder/**

手元で使う場合も、`index.html` をブラウザで開けば動く（サーバー不要・インストール不要）。

画面はダークとライトに対応している（v1.1〜。ページ上部の「自動 / ダーク / ライト」）。「自動」はパソコンやスマホの設定（`prefers-color-scheme`）に合わせる。選んだものは言語と同じく、置き場サイトのほかのツールと共通で覚える。見た目は、ほかのツールと共通のスタイル（置き場サイトのリポジトリの `_dev/design/tool.css`）で、このツールだけの部品は `<style>` の最後にまとめてある。色は `index.html` の `:root` の変数にまとめてあり、ライトでは変数の値だけを差し替える。

## できること

- **条件で絞り込む** — 判型（A4・横長・正方形は、作れると案内している印刷所だけ）、本文のページ数、部数（最少部数で外す）、予算（値段の目安がそれを超える印刷所を外す）、本の中身（小説のセット／本文フルカラー）、表紙と本文（箔押し・特殊な表面加工・特殊紙・表紙の RGB 入稿・カラー口絵が無料・遊び紙が無料）、入稿と支払い（Web で完結・Word のまま・紙の原稿・クレジットカード・届いてから払える）、納品（直接搬入・在庫の預かり・分納・とらのあな・メロンブックス）。条件ごとに、それを足したときに当てはまる社数を出す
- **値段の目安の安い順** — 各社の「表紙フルカラー・本文モノクロ・無線綴じ」の基本のセット（オフセットとオンデマンドのうち安いほう）の、割引なしの通常料金・税込。安い 3 社に「安い順 1〜3」。料金表が公開されていない印刷所や、表に無い判型・部数は、値段を出せない理由を出す。締切はイベント・割引・オプションで変わり 1 つの数にできないので比べない
  - **本文フルカラー**（「本文もフルカラー」を選んだとき、2026-11-07） — 各社の本文フルカラーのセット（表紙・本文ともフルカラー）のうちいちばん安いもので比べる。決まりは基本のセットと同じ（割引なし・税込・表紙込みのページ）。22 社のうち 19 社。**ちょ古っ都**は本文フルカラーの料金表が自動見積りの値段と合わない（B5・本文 40 ページ・50 冊で、表 44,100 円・見積りの 6 営業日コース 34,210 円）ので比べず、理由を出す。小説のセットは値段を出さない
  - 決まったセットの無い 2 社は、自動の見積りから同じ形の本の値段を取った（2026-11-07）: **グラフィック**は料金表示のページ（表紙コート180kg・本文上質70kg、いちばん長い通常の納期）、**ちょ古っ都**は公開の 6 営業日コースの表＋自動見積りの表紙カラーの追加料金。**STARBOOKS**（納品日ごとの早割で値段が変わる）と**ツクヨミ**（見積もりフォームだけ）は値段を出さず、理由を出す。手順は `_dev-local/printers/README.md`
- **印刷所の一覧**（「印刷所の一覧」のタブ、2026-11-07） — 値段の順ではなく名前の順に、各社の最少部数・基本のセット・本文フルカラーのセット・紙の種類（開くと名前の一覧）と、**ほかではあまり見ないこと**（載せている社の半分に満たない社にしか無い「はい」。例: Word のまま入稿 6/22 社）・**多くの社と違ってできないこと**（ほとんどの社ができるのに、その社のページにはできないと書いてあること）を並べる。どちらも事実から数えるだけで、主観の評価はしない
- **印刷所の紹介ページ**（`index.html?p=<id>`） — 最少部数、一覧の条件での値段の目安（基本のセットと本文フルカラー）、料金表の範囲（本文モノクロ／フルカラーのセットごと）、ほかではあまり見ないこと、本の形・加工・入稿・支払い・納品の「はい／いいえ／案内に無し」と、その根拠のページ・印刷所の原文、原稿の決まり（塗り足し・安全域・解像度・インク総量）、紙の種類（背幅の計算フォームにある紙と、その計算に使う厚さ）、背幅の計算（印刷所の式・計算フォームと同じ計算）、根拠のページの一覧、確かめた日
- **表紙入稿メーカーへ** — 紹介ページの「この印刷所で表紙を作る」で、表紙入稿メーカー（`https://shiki365.github.io/cover-print-maker/?printer=<id>&format=<判型>&pages=<本文ページ>`）を、その印刷所の設定で開く
- 日本語・英語・韓国語の画面（ほかの shiki365 のツールと同じ切り替え）。印刷所・紙・セットの名前と印刷所の原文は、印刷所のページで同じものを探せるよう日本語のまま
- 条件はこのブラウザに自動で保存される（どこにも送られない）

## 事実の決まり

- 「はい」は、印刷所の公式ページにそう書いてあるものだけ。根拠のページと、そのページの原文（一字一句そのまま）を付ける
- 「いいえ」は、できないとはっきり書いてあるか、選べるものの一覧に無いもの
- どちらでもないものは「案内に無し」（できないという意味ではない）
- 期間限定のキャンペーンは数えない

### 表紙入稿メーカーとデータを分け合っている

表紙入稿メーカー（`cover-print-maker`）は、`../doujin-printer-finder/papers.v1.js` と `printers.v1.js` を読む（同じ `shiki365.github.io` の下なので、相対パスで届く）。そのため:

- 手元のフォルダ名と公開の名前を同じ `doujin-printer-finder` にしている（手元でも公開でも `../doujin-printer-finder/` で届く）
- 公開するときは両方を出す。どちらかだけでは表紙入稿メーカーが動かない
- データの形（項目名・`window.DoujinPapers` / `window.DoujinPrinters`）を変えるときは、両方のページを一緒に直す。公開後に変えるなら、ファイル名の版を上げて両方の `<script>` も直す
- 辞書の検査（置き場サイトの `_dev/i18n-check.js`）は、ページが `../` から読むスクリプトも検査に入れる

## 確かめ方（手元）

- `.claude/launch.json` の `claude-work-static`（8765、`claude-work` の直下を出す）で `/doujin-printer-finder/` と `/doujin-cover/` を開く（表紙入稿メーカーは `../doujin-printer-finder/` を読むので、`doujin-cover-static` だけでは動かない）
- 辞書の漏れ: `node ../shiki365.github.io/_dev/i18n-check.js .`
- 事実の引用: `_dev-local/facts/` で `python -I -X utf8 verify.py`（`trpg-anthology/.venv` の Python）
- 背幅: `_dev-local/printers/` で `node verify_spine.js pages ../../printers.v1.js`
